## Website updates

Discrete changes to a site that already exists. New pages, copy updates, image swaps, layout adjustments, bug fixes, publishing a post, or a small feature addition.

This is the steady, unglamorous work that keeps a site from going stale, and it is where most of Chapter 2's ongoing hours go after launch. A single new page is a small piece. A multi-page rollout is a real project and we scope it as one rather than absorbing it, because absorbing it is how a month's capacity disappears into work nobody planned.

If an update turns out to require restructured navigation or a new template system, it is a [build](/system/website/design-and-build) wearing an update's clothes. We will flag that before starting, not halfway through.

## Landing pages

A standalone page built for one campaign, event, offer, or lead generation push. One objective, one call to action, tracking wired in from the start.

The distinction from a normal new page is intent rather than effort. A services page is part of the site's permanent structure and has to work for every visitor. A landing page exists to convert one audience on one thing, and everything that would help a general visitor—navigation, alternative paths, related content—doesn't always help it.

Because of that, a landing page is only as good as the campaign brief behind it. If there is no [campaign strategy](/story/strategy/campaign-strategy) naming the audience, the message, and the success number, we would rather write that first than build a page nobody can evaluate afterward.

## What we need from you

For updates, the actual content and a clear statement of what should change. "Make the team page better" generates a round trip. "Replace these three bios with the attached and remove the fourth" does not.

For a landing page, the offer, the audience, the deadline, and where the traffic is coming from. That last one shapes the page more than anything else on the list.

## How long it takes

A single update runs one to two weeks. A landing page runs about a week from an approved brief. Both move faster when the content arrives with the request rather than after it.
